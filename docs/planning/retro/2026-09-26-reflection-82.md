fight the tone classes for specificity) that both branches now keep.

## Pattern / anti-pattern

- **Read the plan/design-research doc before the spec's own literal wording, when they
  disagree.** The spec's Derived Score entity says these scores are "computed from pose
  geometry" and FR-023 asks for "contributing geometry factors" — both wrong. `plan.md`'s
  Constitution Check and the contract itself already corrected this (hand-authored
  integers, friction engine never reads them). Implementing straight from FR-023's prose
  would have produced copy that invents a mechanism to satisfy the letter of the
  requirement while violating Principle II. Always resolve a spec/plan disagreement in the
  plan/contract's favor when the plan says it's a correction, not a contradiction.
- **A "reject these banned words" copy test needs to be negation-aware, not a bare
  substring check.** The contract's own compliant copy says "not calculated" and "not
  derived from the sequencing engine" — a naive `.not.toContain('derived')` would fail on
  the correct copy. Wrote the T055 check to flag the word only when it isn't immediately
  preceded by "not ", the same shape the copy-lint's own `VOICE-REST-LAPSE` rule already
  uses for its rest/lapse co-occurrence. Worth generalizing into the shared copy-lint
  matcher if a third case like this shows up.
- **A CSS class doing double duty (colour + sizing) is a trap the moment one branch needs
  to override only the colour half.** The pre-existing bug here wasn't a missing rule, it
  was `kk-chip`'s sizing and colour both living in one selector, so the "active, per-tone"
  branch had to drop the whole class to get a different background — and silently took the
  touch-target floor with it. Splitting sizing into its own colour-free class before adding
  a tone made the fix a pure addition instead of a specificity fight.
- Nested-button HTML was a real constraint, not a hypothetical: the card's own
  open-detail control is a `<button>` wrapping the whole preview, so the score-explanation
  trigger had to render as a **sibling**, not a nested interactive element, to stay valid
  HTML and to avoid the trigger's click also opening the pose overlay. No `stopPropagation`
  was needed once it was a sibling — worth remembering as the first fix to reach for
  instead of event-handler gymnastics.

## Blocker / codebase insight

No blocker. `npx tsc --noEmit && npm run lint:copy && npm run validate:poses && npm run
lint:telemetry && npm run test:coverage` all passed on the first run after implementation,
with the friction-engine/validator-lite coverage gate (100%) unaffected since this issue
never touches `src/lib/friction/` or `src/lib/validator/`. One thing worth carrying
forward for `005`/`006`: `tests/setup.ts` never loads `src/app/globals.css`, so no unit
test can assert a real computed pixel size (`@media (pointer: coarse)` never matches in
jsdom either) — any future touch-target or motion-budget assertion has to be a source-scan
of the CSS file itself (matching `tests/unit/poses/motion-budget.test.ts`'s existing
shape) plus a DOM check that the right *class name* is present, not a `getComputedStyle`
assertion. That combination is what T056 ended up using and it's a reusable pattern.

Browser validation (Playwright against the Vercel preview) was attempted per the issue's
instructions; see the PR body for whether the preview URL surfaced in time.
