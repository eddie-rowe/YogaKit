## Pattern / anti-pattern

- An issue that itself exists to catch "stale checkbox vs. shipped reality"
  gaps should not be trusted at face value for the *specifics* of its own
  claims — verify each cited line/file directly. Found two claims in this one
  that didn't hold up in detail even though the overall verdict (all seven
  shipped) was correct. Worth treating "confirmed" bullet points in this
  issue shape as a starting pointer to check, not a verified fact.
- Accidentally ran `git checkout main -- .` mid-session while just trying to
  inspect status, which silently reverted the already-committed checkbox
  change in the working tree back to `main`'s stale state (and staged the
  revert). Caught it immediately via `git diff --cached` before doing
  anything else destructive; `git restore --staged --worktree` recovered
  cleanly since the commit itself was untouched. Don't run bare `git checkout
  <branch> -- .` on a path you have uncommitted-adjacent work on, even for
  read-only intent — use `git status`/`git diff` instead of a checkout when
  the goal is just to look.
