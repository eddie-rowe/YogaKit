# Reflection: #301 (RULE-H6 engine-isolation scanner: indirect network sinks, .js/.jsx/.mjs), 2026-11-15

**PR:** #304 (`autodev/301-h6-network-sinks`), merged (squash `6013e0f`)
**Shape:** test-only. Two files under `tests/unit/architecture/`. No file under `src/` changes.

## What went well
- Red was real for most cases. The eight sink cases, the comment-negative case and the six resolution cases all failed on the #298 scanner with a wrong violations list.
- Two cases could not go red against the old code and got their own seeds: the string-literal case (literal-stripped text) and the listing case (old extension list, then the old regex in `listFiles`).
- The real engine tree still reports zero violations under a `fetch` match on the bare name. The walk reaches four files and none contains the word outside a comment.

## What went wrong
- **The first push met the issue's wording and still missed common forms of the same sink.** `(globalThis as any).fetch(`, `window!.fetch(`, `globalThis['fetch'](`, `fetch?.(`, `fetch.call(` and `const f = fetch` all passed. The issue listed three spellings and the first pattern matched those three. The review found the rest by running inputs.
- **The first listing tests could not fail.** They called `isSource` directly, and `listFiles` had no seam, so putting the old regex back in `listFiles` left everything green. Fixed with a `readdir` seam and one in-memory tree.
- **A comment I wrote closed itself.** An example regex in the `stripComments` doc comment contained a star followed by a slash. The rest of the comment became code that happened to parse, tests stayed green, and only an eslint warning showed it. It was on the PR branch for one push and never on `main`.

## Rules worth keeping
- **Match a forbidden name on the bare word, not on one call shape.** A list of spellings is a list of the spellings someone thought of. If the real tree has no legitimate use of the word, the bare word is the rule.
- **A test of a predicate is not a test of the function that uses it.** Seed by reverting the caller, not the helper.
- **Read every lint warning on a file you just edited, even when the gate exits 0.** `eslint` warnings do not fail the gate here.
- **Never write a star-slash inside a block comment, including in an example.**

## Left open
- The shared lexer reads a regex literal containing two slashes, or a slash then a star, as a comment, and JSX text containing `//` the same way. Now written in `stripComments`' known limits. No instance in the guarded directories. Closing it means teaching the lexer regex literals.
- `./foo.js` specifiers that TypeScript resolves to `foo.ts` are still not followed.
- `no-supabase-on-read-path.test.ts` keeps its own copy of the extension list instead of `SOURCE_EXTS`.
- A name assembled at run time (`globalThis['fe' + 'tch']`) cannot be seen by a text scanner.
