# Reflection: #302 (guardrails §1.3: ratchet the no-prefix testid rule), 2026-11-15

**PR:** #305 (`autodev/302-testid-prefix-ratchet`), merged (squash `2e4800e`)
**Shape:** one new test file and a four-line note in `docs/krama-guardrails.md`. No `data-testid` under `src/` changes.

## What went well
- The scan on `main` matched the issue exactly: 147 literal ids, 34 prefix pairs, the same 12 shorter ids. Nothing to report as drift.
- Committing the test with an empty pin list first gave a red run that was also the evidence for the list.
- Collection and the pair check are pure functions over a map of sources, so the planted cases are a few lines each.

## What went wrong
- **The first draft imported a helper that only existed on the #301 branch.** The file collected zero tests on `main`. The autopm handoff had warned about exactly this coupling. Fixed by keeping #302 self-contained.
- **I first asserted "exactly 12 entries".** That would have failed the moment a container was renamed and its entry removed, which is the shrink the issue asks for.
- **The replacement, "at most 12", bounded the count and not the content.** After one removal, a new id could have been pinned in the freed slot. The review caught it. The pin list must now be a subset of a frozen copy of the original twelve.

## Rules worth keeping
- **A ratchet needs two things: it can shrink, and nothing new can enter.** A count gives the first without the second. Check membership against a frozen baseline.
- **Two PRs filed as parallel-safe should not share a new helper.** Duplicate one line and reconcile after both land.

## Left open
- **A live collision the check cannot see:** `settings-org-${id}` (`SettingsClient.tsx:128`) against the literal `settings-org-new` (lines 147 and 194). `[data-testid^="settings-org-"]` over-matches. Not filed; needs `/autopm`.
- Template-literal ids are the larger blind spot: 58 distinct template heads against 147 literals. The incident that motivated the rule (`read-item-`) was a template id.
- Ids held in a variable or prop are not seen (`testId:` fields in `AppHeader.tsx:15-19`).
- The PR body still describes the superseded "at most 12" assertion. The review comment on the PR has the correct account.
- Once #304 is on `main`, this test can use `isSource` instead of its own extension regex.
