## What went well
- Red→green with proof: 12/12 component tests failed first (`bfe90bb`), then went green with no test edits.
- Reusing the `useClientValue` / `useStoredPreference` shape made the hydration criterion trivial: snapshot is a JSON string, so no unstable-snapshot loop.
- Browser validation on the PR's own preview worked first try: `gh api` deployments → bypass cookie → `signInWithPassword` via `eval` → identity verified. `run-code` with locators drove the whole CRUD flow plus a cross-surface check (`/poses/anahatasana` custom checklist reflected an applied preset after reload).

## What the review caught
- **Name-derived testids are a trap.** `settings-preset-rename-${name}` collided with the fixed editor testid `settings-preset-rename-cancel` when a preset is named `cancel`, and broke guardrails §1.3 (kebab-case, no prefix overlap). Fixed: index-based row testids, name in `aria-label`, editor gets its own `settings-preset-renaming-*` family.
- **User-named collections need a unique-name invariant at parse time,** not only at save time: hand-edited / future-synced storage can carry duplicates, which made delete hit two rows. `parsePresets` now keeps the first.

## Rule worth keeping
- Never put user-entered strings into `data-testid`. Use position or a stable id; expose the human name via `aria-label`.
