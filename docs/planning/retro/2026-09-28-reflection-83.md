  predating this issue by three weeks. Verified directly (`layout.tsx`, `globals.css`)
  rather than trusting a research subagent's claim at face value — it checked out. Worth

  task lists from `tasks.md` in the future, T062 should probably be marked done already.

  corpus before trusting the contract's table** — it matched exactly (every row's `n`
  recomputes correctly from base + absorbed counts, total 101). This is the kind of
  check that's cheap to skip and expensive to skip wrongly: a contract this detailed
  earns exactly one verification pass, not zero.
- **A real regression survived my own first pass and was caught by the automated code
  review**: `PoseDetailContent.tsx`'s "Emotional territory" chip used a CSS `capitalize`
  class on the raw emotion string, which mishandles the new hyphenated canonical slugs

  regression test before requesting merge. **Pattern for future sweeps**: when a data
  shape changes, grep for every render site of the changed field, not just the one the
  issue names — `git grep -n "\.emotion\b"` across `src/` would have caught this in one
  pass instead of relying on review to catch it.

  container** — only a deprecated, empty `playwright-cli@0.262.0` npm stub resolves.
  Worked around it with the underlying `playwright` library + pre-installed Chromium
  directly (no `playwright install` run, per the environment's own guidance). That
  substitute then hit a second, unrelated wall: this repo's Vercel preview deployments
  are behind Vercel's SSO deployment-protection, which a headless session has no
  credentials to pass. Both are worth a `007-autonomous-operations` follow-up — the
  first because every future `feat:` sweep will hit the same missing binary, the second
  because it structurally blocks the routine's own "REQUIRED, not deferrable" browser
  validation for any PR whose preview isn't publicly reachable.
