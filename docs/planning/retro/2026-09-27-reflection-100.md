# Reflection — Issue #100

**Issue:** feat(009 US3): operational-writing structural checks (T024/T025, FR-023/FR-024)
**Branch:** `autodev/100-operational-writing-checks`

## What was built

Two pure, unit-tested functions in `scripts/lib/copy-lint.mjs`:

- `checkDecisionFirst` (FR-023) — flags operational writing that buries its decision
  behind a "Background"/"Context"/"Motivation"/"History" heading placed before any
  "Summary"/"Decision"/"TL;DR"/"Ask" heading, and separately flags an opening line that
  starts with a causal conjunction ("Because…", "Since…", "Given that…") — the exact
  shape VOICE.md §2 names as the thing to avoid.
- `checkOperationalHonesty` (FR-024) — flags a `DECISIONS.md`/`FRICTION.md` entry where a
  zero-shipped signal ("0 PRs merged", "nothing shipped") co-occurs with achievement-
  framing language ("productive", "steady progress", "on track") in the same entry — the
  same co-occurrence technique the existing `coOccurrence` rule matcher already uses for
  RULE-C2/C6.

Both are wired into `scripts/copy-lint.mjs`'s CLI as a second pass, run only in the
default (non `--dir`) mode: `checkDecisionFirst` over `docs/planning/retro/*.md` +
`docs/planning/autopm/*.md` (the operational writing the routines actually produce),
`checkOperationalHonesty` over `DECISIONS.md`/`FRICTION.md`.

## Judgment calls a reviewer should double-check

- **Scope of "PR bodies and spec text" (FR-023).** There is no on-disk source for "the
  current PR's body" a static repo scan can read, and the formal `specs/*/spec.md`
  Spec-Kit templates don't open with a decision by design (they open with scenarios).
  I scoped the automatic scan to the actual "operational writing produced by the
  autonomous routines" (FR-023's own wording): the retro and autopm/autodev handoff
  files. `checkDecisionFirst` itself is generic and exported, so it can be pointed at a
  PR body directly from a future caller that has one in hand.
- **DECISIONS.md is out of scope for FR-023 on purpose** — VOICE.md §5 asks it to record
  the reasoning first, the opposite of "decision first". Confirmed this reading against
  the file's own actual entries (`**Context:**` before `**Decision:**` throughout).
- **Ran both checks against every existing file in scope before merging** (`npm run
  lint:copy`) — zero violations. This mattered: a blocking gate that immediately reds out
  on merge day for pre-existing content would be a worse outcome than not shipping the
  check.
- **No exception-marker suppression for either new check** — noted explicitly in
  `coverageLimits()`'s new bullets rather than left undocumented. If a future entry hits
  a false positive, it needs either a rewrite or a follow-up issue to extend
  `parseExceptions`.
- T026 (session-end gates, FR-020) stays explicitly out of scope — still blocked on
  `007-autonomous-operations`, unchanged from the spec's own note.

## Anything worth `autoretro` picking up

- Pattern: when adding a new lint check that scans existing on-disk content, run it
