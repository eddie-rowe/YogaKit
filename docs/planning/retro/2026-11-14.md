## Dev reflection
**Pattern that worked:** the independent review ran inputs against the scanner. Reading the diff would not have found it. The first push of #298 met all seven acceptance criteria and would still have weakened the engine guard, because it moved #293's regex comment strip into the shared helper. The review fed it `'image/*'` and `'//cdn'` and watched real imports disappear.
**Anti-pattern / debt:**
- **Yesterday's retro rule was wrong about the tool.** "Strip comments before scanning" shipped as a regex and went out as a carry item. A regex cannot tell a comment marker inside a string from a comment. The rule is now: strip comments with a lexer, and use the shared one in `import-scan.ts`. A rule this retro hands on should name its failure case, or it spreads the bug it was written to prevent.
- **A safety claim in a code comment is a test waiting to be written.** The helper said a `//` in a string "can only drop text after a specifier, never the specifier itself". That was false and sat on `main` for a day.
- **A case that cannot go red against the old code needs its own seed.** The `// don't` case passed on the old engine regex, so it was seeded by switching off stripping in the new helper.
- **A tick should say which clause the evidence covers.** T045 and T062 are ticked for part of what they name (see the owner banner). Reconcile issues should define "covered" for hosted copy before the sweep, or each sweep decides it differently.
- **Scanner limits left open, unfiled:** `FETCH` misses `globalThis.fetch(`, `XMLHttpRequest`, `WebSocket` and `sendBeacon`. `.js`/`.mjs` files are not walked. Non-literal specifiers are invisible to any text scanner (written down in `import-scan.ts`, accepted).
- **Plan drift:** the 002 `plan.md` Source Code tree lists two paths that were never built and omits several that were (invitations route, billing portal, `src/lib/email/resend.ts`, four migrations).
