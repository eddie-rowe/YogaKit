## Dev reflection
**Pattern that worked:** a guardrail PR ships with its violation grep. #295 audited 48 template-literal testids before stating the rule, so the rule matched the code on day one, with no cleanup backlog. #293 used the same idea for tests: seed the forbidden import, watch the test fail on the exact specifier, revert, then pin a permanent planted case.
**Anti-pattern / debt:**
- **Regex import scanners lose to comments.** In #293, a `// don't` inside a multi-line import list made `[^'"]*?from` stop at the apostrophe, which hid the import. Review caught it, and the scanner now strips comments first. The other source scanners were checked: `lint:telemetry` uses the TypeScript AST, so it does not have this failure mode. Rule: any regex source scanner strips comments first, and its parse test includes a comment containing a quote.
- **Known limit, accepted:** #293 matches forbidden modules on the specifier text, not the resolved path. A relative import of a sync module is still caught one hop later, because those modules import `@/lib/supabase/*`.
