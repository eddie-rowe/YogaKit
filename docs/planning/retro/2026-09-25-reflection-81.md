# Reflection — Issue #81

**Issue:** `datadog-sync.mjs`: `EXPECTED_DRIFT_MONITOR_NAMES` missing
"Synthetic:"/"Synthetic Browser:" infix — drift-check false-positives on all
5 companion monitors

## What changed

`EXPECTED_DRIFT_MONITOR_NAMES` listed the 5 documented synthetics companion
monitors without the `"Synthetic: "`/`"Synthetic Browser: "` infix Datadog
actually prepends, so `findUnexpectedDrift` misclassified every one of them
as unexpected drift on every run of the weekly `datadog-drift.yml` job.
Verified the correct names against each synthetics manifest's own
`monitor_name` field (`datadog/synthetics/{api,browser}/*.json`) rather than
trusting the issue's stated names or `datadog/README.md`'s prose alone —
they matched exactly. Fixed the 5 literals and added a regression test
asserting the exact corrected list.

## Pattern / anti-pattern

- For a "these two strings don't match" bug, the manifest/source-of-truth
  file (here, the synthetics JSON that actually sets `monitor_name`) is a
  stronger verification source than either the issue's prose or a doc file
  describing it — docs can drift too. Checked both and they agreed, but
  would have trusted the manifest over the doc if they hadn't.
- This file was touched by two `ready-for-dev` issues (#76, #81) in the same
  sweep. Building #76 first and rebasing #81's branch on top of it (rather
  than both branching from the same stale `main`) avoided a same-file merge
  conflict entirely — worth defaulting to this stacking whenever two queued
  issues in one sweep name the same file, even if the coupling isn't the
  friction-engine/pose-schema case the routine doc calls out explicitly.

## Codebase insight

`npm run datadog:drift-check` needs live Datadog credentials and can't run
headless in this environment — the only verification path for this class of
bug is a unit test against the manifest-sourced expected values, not the
script itself. Worth keeping in mind for any future `scripts/lib/datadog-*`
fix: the unit test *is* the gate, since the live check isn't runnable here.
