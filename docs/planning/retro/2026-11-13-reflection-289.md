# Reflection: #289 (003 US6a T074 no-Supabase read-path guard), 2026-11-13

**PR:** #293 (`autodev/289-no-supabase-read-path`)
**Shape:** test-only. A static import-graph walk, with no app code change.

## What went well
- Red→green with proof. Seeding `import { createClient } from '@/lib/supabase/client'` into `src/lib/pose-library/index.ts` failed the test with the exact specifier. The seed was reverted, and a permanent in-memory planted-import case keeps the test from passing vacuously.
- Reading the pose route imports first (`grep … from`) showed the graph is small: pose-types, haptics, settings/use-stored-preference, BodyDiagram. That made the expected-green state obvious before writing the test.

## What the review caught
- **Regex import scanners lose to comments.** The pattern `[^'"]*?from` stops at an apostrophe, so a `// don't` inside a multi-line import list hid the whole import. The scanner now strips comments before matching. `require()` is matched too. Both cases are pinned in the parse test.
- A known limit is kept: forbidden modules are matched on the specifier text, not the resolved path. A relative `../storage/sync` is still caught one step later, because sync, sharing and entitlements each import `@/lib/supabase/*`.

## Rule worth keeping
- Any regex-based source scanner (copy-lint, telemetry-lint, import guards) should strip comments first, and its parse test should include a comment containing a quote.
