# Generate Implementation Plan

Creates the full Phase 0/1 planning artifacts for a spec: `plan.md`, `research.md`, `data-model.md`, `contracts/`, `quickstart.md`.

**Spec**: $ARGUMENTS (folder name like `001-daily-priority-briefing`, or empty for most recent)

---

## Steps

### 1. Read all inputs

Read:
- `.specify/memory/constitution.md`
- `specs/$ARGUMENTS/spec.md`
- `specs/$ARGUMENTS/checklists/requirements.md` (if it exists — check it passes before proceeding)
- `.specify/templates/plan.md`

If `checklists/requirements.md` has any unchecked required items, stop and report: "Requirements checklist has unresolved items. Resolve them before generating the plan."

If the spec has open Clarifications (table rows in `## Clarifications > Open questions` with no answer), warn but do not block — note the defaults that will be used.

### 2. Generate `plan.md`

Create `specs/$ARGUMENTS/plan.md` using `.specify/templates/plan.md`. Fill in:

**Summary**: One paragraph — what the feature builds, what UpNext modules it reuses, and what is net-new.

**Technical Context**: Fill from constitution + spec constraints.

**Constitution Check**: Evaluate every principle against the spec. Mark ✅ / ⚠️ / ❌ with one-line rationale per principle. A ❌ blocks proceeding.

**Project Structure**: Generate the full directory tree for both the spec folder and the source code. Reference the UpNext reuse list from the constitution.

**Phase 0 Outputs**: List the specific decisions that Phase 0 research must resolve (tech choices, API decisions, pattern selections). Each output should be a concrete decision, not a question.

**Phase 1 Outputs**: Summary of what data-model.md, contracts/, and quickstart.md will contain.

**Phase 2** (tasks): Note that tasks.md is generated by `/tools:speckit:tasks`.

### 3. Generate `research.md`

Create `specs/$ARGUMENTS/research.md` with the Phase 0 decisions. Each decision:
- **Decision title** (bold)
- Options considered
- Decision taken + rationale
- Any open questions for Phase 1

### 4. Generate `data-model.md`

Create `specs/$ARGUMENTS/data-model.md` with:
- Full SQL `CREATE TABLE` statements for every new table
- All new columns include `NOT NULL` constraints, `CHECK` constraints, FK references with `ON DELETE CASCADE`
- RLS policy for every table using `get_user_business_id()`
- All relevant indexes (FK columns, query columns)
- Migration plan: list each migration file and what it contains

Follow the convention: every table has `business_id UUID NOT NULL REFERENCES businesses(id) ON DELETE CASCADE`.

### 5. Generate contracts

For each integration, API endpoint, or Inngest event introduced by the spec:
1. Create `specs/$ARGUMENTS/contracts/{name}.md` using `.specify/templates/contract.md`
2. Fill all sections: interface, request/response types, behavior, error cases, security constraints, idempotency, observability

Contracts required for any feature that:
- Calls an external API (Shopify, QuickBooks, Gmail, OpenAI, Resend, Twilio)
- Exposes a new HTTP endpoint
- Defines new Inngest event shapes

### 6. Generate `quickstart.md`

Create `specs/$ARGUMENTS/quickstart.md` with a numbered local-dev runbook:
1. Environment setup (`npm install`, `.env.local` from `.env.example`)
2. Database start + migration
3. Background job runner (Inngest dev server)
4. App start
5. Seed script
6. Manual pipeline trigger
7. Preview / smoke test URLs
8. Common issues + fixes
9. Test commands

### 7. Verify

Re-read `plan.md` and check:
- Constitution Check table has no ❌
- Every contract matches what the data model expects
- Quickstart is runnable top-to-bottom with no gaps

### 8. Report

Output:
- Files created (list with line counts)
- Constitution Check summary
- Any ⚠️ items needing attention
- Suggested next command: `/tools:speckit:tasks $ARGUMENTS`
